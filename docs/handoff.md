# oyobidashi 引き継ぎ資料

展示会の呼び出しボタン「oyobidashi」の、これまでの検討内容と次にやることをまとめた資料です。
（2026-10-07 時点。claude.ai での相談内容を Claude Code での開発に引き継ぐためのもの）

---

## 1. 何を作るか

展示会に出展しているとき、**自分がブースを離れている間に来た人がボタンを押すと、持ち歩いている iPhone に通知が届き**、すぐ戻って商品説明ができる仕組み。

体験として大事にしたいこと

- 押した人に「ちゃんと呼べた」とすぐ伝わること（反応がないと連打されるか、帰られてしまう）
- 通知に確実に気づけること（会場は騒がしい）
- お金をかけないこと（今回は **無料で構築** する方針）

## 2. 手持ちの機材

| 機材 | 役割 |
|---|---|
| 大型のメカニカルキースイッチ | 来場者が押す大きなボタン（のちに使わない方針になった） |
| M5Dial | ボタン端末の本体（ESP32-S3、丸型 240×240 液晶、ダイヤル付き） |
| Android スマホ | ブースに置いてテザリング（M5Dial のネット回線） |
| iPhone | 持ち歩いて通知を受け取る |
| モバイルバッテリー | M5Dial（と Android）の電源 |
| M5PaperColor | （任意）ブースの状態表示の看板 |
| iPad（Wi-Fi モデル） | （任意）商品紹介動画のループ再生など。ファームウェアの範囲外 |

## 3. 決まったこと

### 構成

```
 [BIG キースイッチ]
        │ 配線（PORT.B の GPIO）
        ▼
   [M5Dial] ──Wi-Fi(2.4GHz)──▶ [Android テザリング] ──▶ インターネット
        │                                                   │
        │ 画面で来場者にフィードバック                       ▼
        │                                         ntfy.sh/<トピック名>
        ▼                                                   │ プッシュ通知
  「呼び出しました」                                        ▼
                                                 [iPhone の ntfy アプリ]
```

### 判断の記録

| 項目 | 決定 | 理由・経緯 |
|---|---|---|
| 費用 | 無料で作る | まずはコストをかけずに試したい |
| ネット回線 | スマホ2台持ちのうち、Android をブースに置いてテザリング | 会場に Wi-Fi はない。iPhone でテザリングすると、自分が離れた瞬間に切れるので不可。モバイルルーターの契約も不要になった |
| 通知サービス | **ntfy**（ntfy.sh の公開サーバー + iPhone の ntfy アプリ） | 無料・登録不要・HTTP で POST するだけ |
| 不採用：Pushover | 確認するまで鳴り続ける機能は魅力だが有料（約 $5） | 無料方針のため |
| 不採用：LINE Notify | 2025年3月にサービス終了 | — |
| 不採用：IFTTT / Zapier | Webhook 機能が有料プラン限定（のはず） | — |
| 不採用：Android にスイッチを USB 直結し、自動化アプリから通知 | 結局 USB キーボード役のマイコンが必要になり、中継が増えて不安定 | M5Dial から直接 Wi-Fi で送る方がシンプル |
| 電源 | モバイルバッテリー | M5Dial は USB-C で 5V 給電。容量は十分だが、**低電流でバッテリーが自動オフになる懸念**があるので、事前にテストする（下記） |

### 通知と画面の文言（2026-10-07 陽介さんと決定）

- **M5Dial の画面も ntfy の通知も日本語**。デザイン上の装飾・タイトル・UI として英語の方がかっこいい箇所は英語でよい
- 通知のタイトル：「ブースで呼ばれています」
- 通知の本文：「話を聞きたい人がいます！(10:42)」。押された時刻を付ける（Wi-Fi 接続時に NTP で時刻を合わせる。時刻が取れていなければ時刻なしで送る）。iPhone の通知は送った時点の文面のままなので、「x分前」ではなく時刻にした
- 優先度 5、タグ `bell`（🔔）
- iPhone アプリ：[ntfy](https://apps.apple.com/jp/app/ntfy/id1625396347)

### ブースに置く Android のテザリング設定

- 2.4GHz で飛ばす（M5Dial / M5PaperColor は 2.4GHz にしかつながらない）
- 「接続がないと自動でオフ」を無効にする
- 会期中は充電しながら使う（2ポートのモバイルバッテリーで M5Dial と共用するのが楽。Android がつながっていると電流が大きくなり、自動オフも起きにくい）

## 4. 現在の状態

### battery-test/（作成済み・実機で起動確認済み）

モバイルバッテリーの自動オフに引っかからないかを確かめるテスト用ファームウェア。

- 画面に起動してからの経過時間、外周に秒のリング、前回の動作時間（LAST）、明るさ、Wi-Fi の状態、起動回数を表示する
- 経過時間を1分ごとに NVS（本体のフラッシュ）に保存し、給電が切れたあとの次の起動で LAST として表示する
- ダイヤルで明るさを変え（0% が最も厳しい条件）、短押しで Wi-Fi をオン/オフ、2秒長押しで記録をリセットする
- Wi-Fi の設定は `include/secrets.h` に書く（git 管理外。`secrets.example.h` をコピーして作る）
- ビルド確認：Arduino-ESP32 core 3.0.7（arduino-cli、FQBN `esp32:esp32:m5stack_dial`）と、PlatformIO（espressif32 6.12.0 = core 2.0.17、M5Unified 0.2.25）の両方で通った
- 2026-10-07：PlatformIO で M5Dial に書き込み、シリアルログで起動・1分ごとのログ・NVS への保存（LAST）を確認した
  - M5Unified 0.2.x は `Serial.begin()` を呼ばないため、そのままではシリアルに何も出なかった。`cfg.serial_baudrate = 115200;` を追加して解決
  - 書き込みは1回目に「Failed to connect」になることがあり、もう一度実行すると通った

詳しい使い方は `battery-test/README.md` を参照。

2026-10-07 に陽介さんがモバイルバッテリーでテストし、**約22分（記録上 1320秒）動き続け、自動オフは起きなかった**。展示会の1日分の長時間テストはまだしていない。

### call-button/（完成・実機で確認済み。イベントに投入できる状態）

画面・音・通知・ダイヤル操作の設計は **docs/ux-proposal.html** にまとめた（実機と同じ動きのプロトタイプ付き）。操作と状態の一覧は `call-button/README.md`。

- 来場者は画面に触れて呼ぶ（タッチ・押し込みどちらでも）。**BIG スイッチは使わない方針になり、G1 の入力は外した**
- 待機画面は「TAP / 制作者と話してみたい！」。色の意味は、オレンジ = 触れる番、黒 = 待つ番、白 = QR を見る番
- 通知には返事のボタン3つ（向かいます / 5分で戻ります / 30分で戻ります）。M5Dial は `NTFY_TOPIC-reply` を待ち受けて、画面に「制作者が向かっています」「12:15 ごろ戻ります」を出す。通知のタップは返事にしない
- 1分で QR（行き先は `QR_URL`）、2分で再通知、5分で「お待たせしています」に区切る
- ダイヤル：待機中は外周の光が追従、待っている間は製品カード（`CARDS`。リポジトリにはサンプルを入れている）、触れたまま回すと担当者メニュー（在席・離席・戻り時刻・音量）
- 日本語は Noto Sans JP のなめらかフォント（`tools/make_vlw.py` で使う文字だけを取り出す）
- 通信は別タスク1本で、送信と返事の待ち受けを順番に行う（TLS を同時に2本張らない）。ntfy.sh の制限（60回まで、その後は5秒に1回）に引っかからないよう、返事は1本の接続で待ち受ける
- 触れてから届くまで約2.5秒。体感は触れた瞬間の音と波紋で補う
- 2026-10-07：陽介さんが実機で全機能を確認し、「イベントに即投入できそう」との評価

### 公開用のリリース（2026-11-03・実機未検証のトライアル版として公開）

部材を全部持っている人が、ツールを入れずに使えるようにした。作者は実機で試さない方針（2026-11-03）なので、README・手順書・書き込みページ・リリースに「実機未検証のトライアル版（おまけ）」と明記し、GitHub のリリースもプレリリース扱いにした。GitHub Actions でのビルドは通っている。

- **設定モード**（`call-button/src/portal.cpp`）：配布するファームウェアに秘密情報を入れられないので、M5Dial が Wi-Fi の親機（`oyobidashi-XXXX`、パスワードは起動ごとにランダム）になり、スマホのブラウザからテザリング・トピック名・QR の行き先を入れてもらう。値は NVS に保存し、`secrets.h` より優先する。設定がないとき、または画面を押したまま電源を入れたときに入る
  - 画面（**デザイン提案中・陽介さんの確認待ち**）：白地 =「設定モード」+ 接続用 QR + SSID / PASS → スマホがつながると黒地 =「SETUP / スマホの画面で設定を続けてください」→ 保存で「OK / 保存しました / 再起動します」。設定済みなら3秒長押しでやめられる
  - トピック名は本体の乱数で `oyobidashi-` + 16桁を初期値にする（「作り直す」でブラウザ側でも作れる）
  - 追加した文字だけをフォントに足し、既存の文字のグリフはそのまま残した（ダウンロードできた Noto Sans JP が元のものと版違いで、ラスタライズが少し違ったため）
- **配布用ビルド**（`pio run -e release`）：`secrets.h` を読まない。製品カード（サンプル）は出さない。QR の初期値は空で、空なら QR を出さない（届いた画面は1分たっても黒のまま、不在・お待たせは QR なしの配置）。この QR なしの配置も**デザイン確認待ち**
- **書き込み**：`docs/flasher/index.html`（ESP Web Tools）を GitHub Pages に置き、Chrome / Edge から書き込めるようにした。1つにまとめた bin はすき間を 0xFF で埋めて NVS も消すので、ブラウザでは部品ごと（bootloader / partitions / boot_app0 / firmware）に書く。esptool 用には1つにまとめた bin をリリースに添付（設定は消える）
- **GitHub Actions**（`.github/workflows/firmware.yml`）：プッシュごとにビルド確認。リリースは Actions → firmware → Run workflow（main・version に v1.0.0 など）で、タグ・プレリリース・Pages の公開までする（Pages の公開先 github-pages は main からしか受け付けないため。Claude Code の環境からはタグをプッシュできなかった）。Pages は Settings → Pages → Source を「GitHub Actions」にする必要がある
- 手順書：`docs/setup/quick-start.md`。README の一番下に免責事項を追記

## 5. 次にやること

1. **M5Dial を埋め込むプレート**（2026-10-07 レイアウト B で確定・STEP / STL 書き出し済み・造形前）
   - 横長 170 × 110 × 3 mm。文字を 0.8 mm 盛り上げて2色で造形する。手持ちの色はイエロー・ブラック・グレー
   - 文字は日本語だけ（見出しのドット「MAKER CALL」、一文、3ステップ）。英語・ダイヤルの説明・ロゴは入れない（2026-10-07 レビュー）
   - 固定：M5Dial の背面のネジ（Ø44）を穴 Ø44.6 に通し、付属のネジ式のリング（Ø50.8、高さ 5 mm）で挟む。プレートが厚いとリングが真下の USB-C をふさぐので 3 mm（挟める厚さは約 3.5 mm まで）
   - スタンド：左右の側板の溝にプレートの端を差し込み、地面から 20° に寝かせる。前の端を机から 20 mm 浮かせて、裏の M5Dial・USB-C のプラグ・バッテリーの逃げを確保
   - レイアウトは **B（上に見出しと一文、下にダイヤルと3ステップ）に確定**。比較した A / C も docs/plate-design.html に残してある
   - モデル：`plate/make_plate.py` → `plate/out/`（plate_base / plate_raised / frame_left / frame_right / fit_test の STL と STEP、組み立ての oyobidashi_plate.step）
   - 色の組み合わせ（イエロー・ブラック・グレーのどれを地と文字にするか）は、造形のときにスライサーで決める
   - 造形前に `fit_test.stl`（60 mm 角の試し板）で、挟めるか・USB-C が挿せるか・回るリングがこすれないかを確かめる
   - 画面の向きは、担当者メニューの「画面の向き」で 10° 刻みに合わせられる
2. **展示会1日分のバッテリーテスト**（必要なら。約22分では自動オフは起きなかった）
3. **iPhone の集中モード中に通知が届くか**を確かめて、README に追記する
